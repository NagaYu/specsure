# ベンチ収集プロトコル（Phase 3 以降に人が手動で実施。Phase 2 では文書化のみ）

SpecBench 本走行で、実在の買い物エージェントの回答を収集するための手順。
**自動クエリ送信はしない**（スクリプト・ブラウザ自動操作・API による一括送信は禁止）。人がエージェントの通常 UI で質問し、回答を記録する。

## 1. 事前条件

1. 下の「対象エージェントと規約確認」表で、対象エージェントの規約確認が **人によって** 済んでいること（Claude Code は規約を断定しない）。
2. 質問対象の商品が、`data/seed/` または `data/real_pilot/` のカタログにあること（GTIN/JAN・型番・商品名のいずれかで同定できる）。
3. 収集者は個人アカウントの個人情報（氏名・住所・購入履歴）が回答に含まれない状態で質問する。含まれた場合は記録しない。

## 2. 固定質問セット

質問文は [configs/question_sets.yaml](../configs/question_sets.yaml) のものをそのまま使う（改変しない。`{product}` だけ置換）。

| カテゴリ | 質問 ID | 引き出したい claim |
|---|---|---|
| 充電器 | chg-01 / chg-02 / chg-03 | 数値 / 互換性 / 同梱物 |
| インク | ink-01 / ink-02 | 互換性 / 数値 |
| イヤホン | ear-01 / ear-02 | 数値・互換性 / 同梱物 |
| スマホケース | case-01 | 互換性・バリアント |
| ケーブル | cab-01 | 数値 |
| ドライヤー | dry-01 / dry-02 | 数値・地域仕様 / 同梱物 |
| 食品 | food-01 / food-02 / food-03 | 成分・アレルゲン / 不使用の主張 / 内容量 |
| 化粧品 | cos-01 / cos-02 | 成分 / 容量 |

## 3. 手動収集の手順

1. エージェントの UI を開き、画面に表示されているバージョン・モデル名を **表示どおり** 記録する（無ければ `"not shown"`）。
2. 新しい会話を開始し（前の会話の文脈を持ち込まない）、質問を 1 つだけ送る。
3. 最初の回答を **原文のまま** コピーする（要約・翻訳・整形しない）。追加質問はしない。
4. スクリーンショットはローカルに保存してよいが、**git には入れない**（`screenshot_ref` にはローカルのファイル名だけ書く）。
5. 下の記録フォーマットで JSONL に 1 行追記し、バリデータを通す。
6. 抽出・照合は後段（`src.extract` → `src.verify`）で行い、`extractor_version` を記録に残す。

## 4. 記録フォーマット（JSONL、1 行 1 回答）

| フィールド | 必須 | 内容 |
|---|---|---|
| `record_id` | ✓ | 一意 ID（例 `2026-11-05-agentA-ink-01-001`） |
| `collected_at` | ✓ | 収集日時（ISO 8601、タイムゾーン付き） |
| `agent_name` | ✓ | エージェント名（表の「エージェント」列と同じ表記） |
| `agent_version_displayed` | ✓ | UI に表示されたバージョン・モデル名（表示どおり。無ければ `not shown`） |
| `question_id` | ✓ | configs/question_sets.yaml の ID |
| `question_text` | ✓ | 実際に送った質問文（置換後） |
| `product_ref` | ✓ | `{gtin}` / `{model_number}` / `{name}` のいずれか |
| `answer_text` | ✓ | 回答原文（8,000 文字以内） |
| `collector` | ✓ | 収集者の仮名（メール・電話番号は書かない） |
| `terms_check_ref` | ✓ | この文書の規約確認行へのアンカー（例 `docs/collection-protocol.md#agent-a`） |
| `agent_surface` | | web / app / voice など |
| `locale` | | ja-JP / en-US |
| `extractor_version` | | 抽出時に付与（例 `extract-rules/v1`） |
| `screenshot_ref` | | ローカル保存したスクリーンショットのファイル名（git 外） |
| `notes` | | 特記事項（個人情報を書かない） |
| `synthetic` | | 合成データの場合 `true`（ClaimWatch の見本など） |

検証:

```bash
.venv/bin/python -m src.cli validate-records path/to/records.jsonl
```

## 6. やらないこと

- 自動化ツールでの質問送信・回答取得、レート制限の回避
- ログインが必要な画面の情報（購入履歴・住所等）の記録
- 回答の要約・翻訳・修正（原文のみ）
- 規約確認が済んでいないエージェントからの収集
